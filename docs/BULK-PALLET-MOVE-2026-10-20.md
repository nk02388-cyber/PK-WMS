# Move multiple pallets — 20 October 2026

Uses the existing zone selection toolbar. Select occupied pallets in one source zone, choose Move, and assign each source a distinct empty slot in a destination zone. Enter a Bangkok-default move date and reference, then verify with the existing own-account password/PIN/reason confirmation. Source/destination pairs are displayed before confirmation. Cross-zone moves and moves within the same zone are supported; swapping occupied slots or merging multiple pallets into one destination is outside this workflow.

`buildBulkSlotMovePlan` calls the existing `buildSlotMovePlan` with whole-item selections. Quantities, original units, lots, receipt dates and receipt/withdrawal/return history are carried exactly once. Each item gains its normal location-move entry. Source slots become empty; destination slots become occupied. It rejects duplicate source/destination keys, overlapping source/destination sets, occupied destinations, empty sources and invalid versions. UI checks destination geometry and snapshots/rechecks both ends' versions after confirmation. A single `save_pallet_changes` transaction receives all source and destination rows with transfer audit metadata linked to the confirmation ID. No schema changes or new permission grants.

Validation: two new core tests cover preservation and rejection cases. Edge and WebKit browser tests cover desktop/mobile controls, duplicate destinations, cancellation without writes, server conflict without local mutation, stale destination rejection, account change during confirmation, whole-batch success and history preservation. Existing bulk deletion, single-pallet copying and action confirmation tests also pass. Full Node regression: 125 passed, zero failed. Only fixtures were moved; production verification remains read-only. Physical devices were not tested.
