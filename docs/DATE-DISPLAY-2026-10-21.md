# DD/MM/YYYY display — 21 October 2026

Implemented human date presentation throughout PK WMS and the embedded Operations application. Day dates show **DD/MM/YYYY (Gregorian)**; date-times retain time in Bangkok. Month-only calendar/analytics headings show MM/YYYY. Numeric source dates and legacy Thai report dates/BE years are validated and normalized for display. Missing or invalid dates show “—”.

Covered: FM-ST-019 ordinary and existing-balance labels (received/manufactured/expiry), Count Sheet print stamp, stock Dashboard/report metadata, movement stock cards, daily lists, product history, stock reconciliation cutoff, reorder reference, cycle-count schedule/draft/history and CSV, scrap history/CSV, calendar headings/accessibility labels and reminders, pallet audit, recipe versions, imported receipt-plan table/status, Operations ticket/audit/print dates, planning/analytics/report scopes, and holidays. Receiving/stock quantities and QR payloads are unchanged.

`date-display.js` is a presentation helper loaded before the main application. Native date controls keep YYYY-MM-DD values and their calendar behavior. UI markup declares en-GB; the native picker appearance remains browser/OS controlled. ISO timestamps/date keys remain authoritative for APIs, sorting, filters, calculations, persisted JSON and backups. Holiday text entry shows DD/MM/YYYY and adapts back to ISO before existing settings validation. No database migration or inventory/data write is part of this change.

Verification: full Node suite 128/128; shared formatter tests cover Thai/BE dates, leap days, invalid values, missing dates, Gregorian years and Bangkok day transitions. Edge/WebKit desktop/mobile fixtures check real stock metadata, stock-card/daily timestamps, dashboard table, calendar dates, receipt-plan status, Operations tickets/audit, both label paths, preserved date-input values and exact unchanged item data. Existing Count Sheet and online count workflows also checked. Physical printer and phone hardware remain untested.
