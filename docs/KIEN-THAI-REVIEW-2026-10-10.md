# ตรวจภาษาและข้อความการทำงาน PK WMS

วันที่ 10 ตุลาคม 2026 ใช้ `kien-thai` จาก ZIP ที่ผู้ใช้ส่งมา เลือกน้ำเสียงอธิบายงานคลังตรงไปตรงมา อ่าน SKILL และเอกสารอ้างอิงครบ 8 ไฟล์ แล้วใช้ขั้นตอนอ่าน → ระบุข้อความและกฎ → แก้ → อ่านใหม่ ตาม `kode-thai` ที่อยู่ใน ZIP เดียวกัน

## ขอบเขต

ตรวจคำอธิบาย คำแนะนำ ข้อความแจ้งผล และสถานะโหลดข้อมูลใน Login, Settings, ประวัติสินค้า, สูตรและแผน BOM, รับเข้า/จัดเก็บ, คัดลอกพาเลต, ตรวจนับ, Scrap, ปฏิทิน, แผนรับเข้า, การแจ้งเตือน, ไฟล์ส่งออก และ Operations ตรวจข้อความจาก HTML/JavaScript 37 ไฟล์เพื่อค้นหาจุดที่ควรปรับ ไม่เปลี่ยนชื่อสินค้าหรือข้อความจากข้อมูลธุรกิจ

สกิลนี้ใช้ตรวจภาษาไทย ผลรอบที่ไม่พบข้อแก้เพิ่มหมายถึงข้อความในขอบเขตนี้ตามเกณฑ์ที่ใช้ และกรณีการทำงานที่ทดสอบ ไม่ใช่การรับรองว่าเว็บไซต์ไม่มีบัคหรือช่องโหว่ทุกกรณี

## รอบตรวจและแก้

| รอบ | สิ่งที่พบและแก้ |
|---|---|
| 1 | แก้ข้อความ 15 จุด: คำแนะนำ Login ไม่ตรงกับประเภทบัญชีที่ตั้งได้ ชื่อผู้ใช้ใหม่ไม่บอกเงื่อนไขตัวอักษรแรก ข้อความสำรองสต็อกค้าง ประโยคยาวและเครื่องหมายแบ่งประโยคในประวัติ/ไฟล์ส่งออก ข้อความตรวจนับและ Scrap รวมถึงคำแนะนำเบิกจริง แก้ตัวแปรที่ไม่ได้ประกาศในคำสั่งอัปเดตสต็อกด้วย |
| 2 | อ่านคำอธิบายและข้อความแจ้งผลต่อจนจบ พบอีก 9 ตำแหน่ง: ปฏิทินใช้คำว่าวันนี้แทนวันที่เลือก ข้อความสำรองสต็อกค้างในไฟล์ส่งออก 2 จุด การแจ้งเตือนตรวจสถานะ fallback ที่เลิกใช้ และปรับภาษาในรับเข้า คัดลอกพาเลต ถังขยะ และคำแนะนำส่งออก |
| 3 | ตรวจซ้ำหลังแก้ พบว่าการเริ่มอัปโหลดเร็วเกินไปอาจยกเลิกผลโหลดสต็อกเดิมแม้ผู้ใช้ยกเลิกอัปโหลด ย้ายจังหวะตรวจเวอร์ชันไปหลังยืนยัน PIN และปรับประโยคอธิบายยอดสะสมให้อ่านตรงขึ้น |
| 4 | ตรวจคำแจ้งผลกับเส้นทางผิดพลาด ปรับเป็น “ยังยืนยันการอัปเดตไม่ได้” เมื่อผลตอบกลับไม่ครบ ตรวจโครงสร้าง warehouses ก่อนแสดงผล และแก้ baseline ใน PRD ที่ยังระบุว่ามี static fallback |
| 5 | อ่านชุดข้อความที่แก้ใหม่และตรวจคำต้องห้าม/ข้อความเก่าค้าง ไม่พบข้อแก้เพิ่มตามเกณฑ์ภาษาและความหมายที่ตรวจ |
| 6 | ตรวจยืนยันอีกครั้งหลังแก้ครบ ไม่พบข้อแก้เพิ่มในชุดเดิม ตรวจการเปลี่ยนแปลงและไฟล์ข้อมูลที่ต้องรักษาประกอบด้วย |

## กฎและตัวอย่าง

| ข้อความเดิม | สิ่งที่แก้ | กฎ / หลักฐาน |
|---|---|---|
| `ผู้ใช้ย่อยใช้ PIN 6 หลัก · Admin ใช้รหัสผ่าน` | ใช้ PIN หรือรหัสผ่านตามที่ตั้งไว้สำหรับบัญชี | `source-fidelity`: Settings เลือกได้ทั้งสองประเภท |
| `ภาษาอังกฤษ 3–32 ตัวอักษร ใช้ตัวเลข . _ - ได้` | ระบุว่าต้องขึ้นต้นด้วยตัวอักษรภาษาอังกฤษ และใช้ชื่อใหม่หลังบันทึก | `conceptual-seam-break`, `source-fidelity`: ตรงกับ pattern ของช่องชื่อ |
| `สต็อกสำรองในไฟล์` และ `ข้อมูลสำรอง/ยังไม่ยืนยันล่าสุด` | แสดงตามสถานะล่าสุด/กำลังโหลด/ไม่มีสิทธิ์/โหลดไม่สำเร็จ และระบุสถานะจริงในรายงาน | `source-fidelity`: ระบบถอดข้อมูลสำรองแล้ว |
| `ซิงค์ทุกเครื่องแล้ว` | `โหลดปฏิทินล่าสุดจากระบบแล้ว` | `source-fidelity`: การโหลดสำเร็จยืนยันได้เฉพาะข้อมูลที่เครื่องนี้รับ |
| `ยังไม่มีกิจกรรมในวันนี้` | `ยังไม่มีกิจกรรมในวันที่เลือก` | `source-fidelity`: ปฏิทินเลือกวันอื่นได้ |
| `ยอดสต็อกจริงยังไม่ถูกปรับ` | `ระบบยังไม่ได้ปรับยอดพาเลตหรือสต็อก` | `non-adversative-thuk`, `active-voice-default` |
| คำอธิบายประวัติและ Excel ใช้ semicolon แบ่งประโยค | แยกช่วงความคิดด้วยช่องว่างและคำเชื่อมตามลำดับ | `em-dash-semicolon`, `conceptual-seam-break`, `seam-connective-missing` |
| คำแนะนำเบิกจริงไม่ระบุว่าเติมยอดให้ก่อน | ระบุการเติมยอดตามใบเบิก การตรวจยอดจริง และเงื่อนไขเหตุผลส่วนต่าง | `topic-comment-fronting`, `missing-cha-modal`, `source-fidelity` |

เครื่องหมาย `—` ที่ใช้แทนค่าที่ไม่มี รหัสสินค้า ตัวเลข หน่วย และสูตรคำนวณยังคงความหมายเดิม คำแนะนำตรวจนับยังแจ้งว่าเก็บในเบราว์เซอร์เครื่องนี้ และไม่ปรับยอดคลังอัตโนมัติ

## บัคอัปเดตสต็อก

คำสั่งเดิมเขียนผ่าน `replace_stock_inventory` แล้วอ้าง `accountGeneration` ที่ไม่ได้ประกาศ จึงอาจบันทึกสำเร็จแต่แสดงผลล้มเหลว ตอนนี้จับเวอร์ชันการโหลดก่อนอ่านไฟล์ ตรวจซ้ำก่อนเขียน และไม่ยอมให้ผลจากบัญชีเก่ากลับมาแสดงหลังเปลี่ยนบัญชีหรือออกจากระบบ

ใช้ผลอัปเดตที่เซิร์ฟเวอร์ส่งกลับโดยตรง ไม่โหลดซ้ำแล้วเขียนทับข้อความสำเร็จ ยกเลิก PIN ได้โดยไม่เขียนข้อมูลและไม่ยกเลิกการโหลดเดิม หากผลตอบกลับขาดข้อมูล จะแนะนำให้โหลดหน้าใหม่เพื่อตรวจสต็อกก่อนลองอัปเดตซ้ำ

## การตรวจยืนยัน

- `node --test tests/*.test.cjs tests/*.test.mjs`: ผ่าน 102 รายการ รวมกรณีอัปเดตสำเร็จ เปลี่ยนบัญชีระหว่างอ่านไฟล์ ออกจากระบบระหว่างรอผล ความผิดพลาดที่มาช้า ยกเลิก/ไม่มีสิทธิ์ และผลตอบกลับไม่ครบ
- `tests/auth-flow-browser.cjs`: Login/เลือกแผนก ผ่านที่ 1440 และ 390 พิกเซล
- `tests/settings-browser.cjs`: Admin และผู้ใช้ทั่วไป ผ่านที่ 1440 และ 390 พิกเซล รวมเปลี่ยนชื่อ/รูป/PIN ด้วย fixtures
- `tests/private-data-browser.cjs`: โหลดข้อมูลตามสิทธิ์ ผลเก่าหลัง logout ล้มเหลว/ลองใหม่ และการแจ้งเตือนล้มเหลวที่หายเมื่อกู้คืน ผ่านที่ 1440 และ 390 พิกเซล
- `tests/browser-stability.cjs`: 16 เมนู แผนผัง และโฟกัสฟอร์ม ผ่านที่ 1440, 768 และ 390 พิกเซล
- `tests/operations-keyword-browser.cjs`: ค้นหา 6 ช่อง ผ่านที่ 1440 และ 390 พิกเซล
- ชุดตรวจข้อมูลและรูปแผนผังเดิมผ่าน ไม่แก้ยอดสต็อก สูตรธุรกิจ หรือบัญชีจริงเพื่อทดสอบ

ใช้ fixtures/mocks สำหรับคำสั่งเขียน การตรวจเว็บจริงเป็นการเปิดหน้าและอ่านไฟล์ที่เผยแพร่ ไม่ส่งคำสั่งเขียนสต็อกหรือบัญชีจริง
